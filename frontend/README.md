# ExamSensei — Frontend

TanStack Start app (Vite 7 + React 19 + Tailwind v4 + shadcn/ui) that serves
both the landing page and the authenticated product. Deployed to Vercel; auth
via Supabase; data from the FastAPI backend.

For the bigger picture (architecture, stack choices, repo layout) see the
[root README](../README.md). For deployment see [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md).

---

## Requirements

- **Bun** 1.3+ (the project ships `bun.lock` and `bunfig.toml`)
- A **Supabase** project (URL + anon key)
- The **FastAPI backend** reachable at `VITE_API_URL`

---

## Local setup

```bash
cd frontend
bun install
cp .env.example .env          # then fill in the VITE_SUPABASE_* values
bun run dev
```

App at <http://localhost:3000> (or whatever port Vite picks). The landing
loads without any env vars; auth and product screens need `VITE_SUPABASE_*` +
a reachable backend.

---

## Env vars

All vars are `VITE_*`-prefixed (Vite only exposes those to the client).

| Var | Purpose |
|---|---|
| `VITE_API_URL` | FastAPI base URL, e.g. `http://localhost:8000/api/v1` |
| `VITE_SUPABASE_URL` | Supabase project URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase `anon public` key |

## Route map

```
/                            Landing (SSR — Hero / Manifesto / MentorConsole / FAQ / CTA)
/login                       Sign in (Supabase password)
/signup                      Create account (+ ?email= ?exam= from landing CTA prefill)
/app                         App shell — client-side auth guard, sidebar nav
  /app/                      Dashboard (gamification + recommendations)
  /app/exams                 Exam browse
  /app/exams/$id             Exam detail
  /app/chat                  AI mentor (real chat over /users/{uuid}/chat)
  /app/study-plan            Study plan builder (?exam= prefill from detail)
  /app/profile               Profile editor (career_paths, active_exams, prep profile)
```

The auth guard lives in `src/components/app/AppShell.tsx` (client-side, so it
plays nicely with SSR — Supabase's session lives in `localStorage`, which the
server can't read). Unauthenticated visits to `/app/*` get redirected to
`/login`.

## Where to find things

| File | Responsibility |
|---|---|
| `src/styles.css` | Design tokens — Paper & Ink palette, fonts, `.grain`, `.eyebrow`, `.display`, `.hatch` |
| `src/lib/supabase.ts` | Browser Supabase client (SSR-safe) |
| `src/lib/api.ts` | Typed fetch client. Attaches `Authorization: Bearer <session.access_token>` and unwraps the backend's `{detail:{message,details}}` error envelope into `ApiError` |
| `src/lib/auth.tsx` | `AuthProvider` / `useAuth()` — wraps Supabase session, exposes `signIn` / `signUp` / `signOut` |
| `src/components/auth/AuthLayout.tsx` | Editorial frame for `/login` and `/signup` |
| `src/components/app/AppShell.tsx` | Authenticated app layout (sidebar, topbar, mobile bottom nav, guard) |
| `src/components/landing/*` | Landing sections — Hero, Manifesto, ProductReveal, SignalRadar, Cryptex, MentorConsole, EditorialSpread, ProofMarquee, FAQ, FinalCTA |
| `src/components/ui/*` | Full shadcn/ui (new-york style). Used across product screens. |
| `src/routes/*` | File-based routes. `routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin`. |

## Design tokens (quick reference)

- **Background**: `bg-paper` / `bg-paper-2` / `bg-paper-3`
- **Text**: `text-ink` / `text-ink-dim` / `text-ink-soft`
- **Accent**: `text-ember` / `bg-ember`
- **Fonts**: `font-display` (Space Grotesk), `font-sans` (DM Sans, default), `font-mono` (JetBrains Mono)
- **Utilities**: `.display` (oversized headlines), `.eyebrow` (mono caps tracked-out), `.grain` (fixed noise overlay), `.hatch` (diagonal hatch)

Stick to these for new screens — that's how the app stays coherent.

## Deployment (Vercel)

Vercel detects TanStack Start automatically. The only setup is:

1. Vercel project **Root Directory = `frontend`**.
2. Build command + output: detected automatically.
3. Environment variables: set the three `VITE_*` vars above.
4. Add the resulting Vercel domain to the backend's `ALLOWED_ORIGINS`.

Full step-by-step in [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md).
